# 制度事项与办理规则建模设计

## 目标与首版边界

将已入库的学校制度条款整理为可追溯的办事卡。系统面向多份制度批量运行，支持事项发现、同文证据归集、规则抽取、字段证据校验、复核、增量失效检测。模型负责候选理解，程序负责可以确定验证的约束；不把结构校验通过等同于业务语义正确。

这是独立于 `policy/graph` 和 `policy/knowledge_v2` 的新模块，不迁移旧断言，不将旧候选默认为正确事实。复用条款层级、原文位置、文档元数据、效力处理、数据库适配器和模型客户端。

首版交付：

1. 按制度 ID 或批次发现办理事项；非办理条款保留分类记录，不强行生成流程。
2. 为事项归集当前文档中的条款，处理分散在不同章节的条件、材料、程序及例外。
3. 生成包含多种办理情形的办事卡，每个确定字段都能回查原文。
4. 输出原文和抽取结果并列的本地 HTML 复核报告，以及可导入的 JSON 复核文件。
5. 保存运行、候选、复核结论和来源快照；来源变化后标记卡片过期，按受影响制度重建。
6. 使用住宿调整等少量真实事项运行、核查；通过验证后才建议扩大批次。

暂不交付：正式问答自动使用未审核卡片、完整知识图谱、图数据库、自动判定个人资格、自动解决制度冲突、隐含跨文依赖的自动确立。跨文补充作为独立可选候选来源，不拼接未经确认的事实。

## 方案比较与选择

纯 JSON 原型容易实现，但运行恢复、来源变化和审核历史难维护。图数据库优先会增加存储体系，同时仍需解决规则抽取。选择现有 PostgreSQL 中的独立表、JSONB 办事卡和来源关联表；关系视图可以以后从已核实卡片派生。

首版使用已有 `LLM_*` 抽取模型配置，但提供独立模型配置覆盖入口；不改动正式问答模型及默认检索流程。当前本地 7B 模型的抽取质量是风险，需要保留原始响应和失败原因，不能通过降低证据要求制造成功率。

## 模块边界

新增 `policy/service_cards/`：

- `models.py`：事项候选、字段证据、办理情形、规则步骤、复核结论及状态。
- `discovery.py`：构建章节/条款窗口，发现事项并归并同文重复候选。
- `evidence.py`：归集目标条款、上下文和同文补充条款；维护来源快照。
- `extraction.py`：提取卡片、解析模型响应、有限反馈重试。
- `validation.py`：结构、来源、片段、角色引用、顺序和状态约束。
- `repository.py`：独立表、事务、运行恢复和审核历史；避免继续扩大 `policy/storage.py`。
- `runner.py`：批次/制度任务、检查点、增量跳过与过期检测。
- `review.py`：安全转义 HTML、JSON 导出/导入、并发修改检查。
- `cli.py`：模块命令行入口，先独立于复杂的既有 `main.py` 参数表。

上述边界允许分别测试纯逻辑、模型输出处理和真实数据库存储，不依赖 LLM 的回归测试必须可离线执行。

## 数据结构

### 原文引用

`EvidenceRef` 保存 `policy_id`、`clause_id`、原文 SHA-256、连续 `quote`、左闭右开的 `start/end`。页码、条号和标题从来源条款读取，不信任模型生成。

证据必须属于本次实际提供给模型的来源集合。偏移不正确但片段在该条款唯一出现时，允许重新定位，并保留修复记录；不拼接证据，不模糊匹配，不改写原文来适配模型。

### 字段取值

每个字段由 `value`、`evidence[]`、`state` 构成。

- `supported`：有来源支持的机器候选，仍不代表已审核。
- `not_found`：已提供材料中未提取到，不能表述为全校制度没有规定。
- `ambiguous`：存在多种解释，需要确认。
- `conflicting`：来源给出无法直接兼容的候选值，分别保留依据。

空值不得自动补全。模型无法填出的审批部门保存为 `not_found`，不拿执行部门代替。只有原文明确说明某内容不要求时，才允许以有证据的否定值表达，而不是用空值表达。

### 办事卡

卡片保存：事项名称、描述、申请对象、办理情形 `variants[]`、来源集合、未解决问题、审核状态、版本和来源指纹。

每个办理情形保存：触发条件、资格要求、禁止条件、材料、申请时间、办理期限、步骤、结果、例外及适用范围。普通办理和特殊办理分别建情形，避免将不同条件混成一条流程。

条件用 `all` / `any` / `not` 和有证据的条件原子表达；不能用一个没有连接词语义的字符串数组承载复杂资格判断。第一版不执行条件表达式以判定用户资格，只用于准确存储和展示。

期限必须保留原文，并可选保存数量、单位和起算事件。金额必须保留原文，并可选保存数值、币种、计算周期；未明确的部分保持空值。

步骤保存动作、动作主体、接收方、角色类别（申请/受理/审核/批准/执行/备案）、前置条件和依据。原文顺序仅用于展示；步骤先后关系必须有明确文字依据才能标记为已确认，禁止从条款排列推导业务顺序。

### 审核状态

机器结果只能处于 `draft`、`needs_review`、`invalid`，不能自动变成 `approved`。人工结论为通过、修正或拒绝，保存审核者、时间和备注；修正后的卡片重新通过同样的证据校验。

`stale` 独立于审核结论：已经审核的卡片，其来源变化后仍保留原审批历史，但当前视图标记过期，不能冒充最新卡片。

## 发现与归集流程

1. 按当前制度结构版本加载有序条款，构建父子层级。标题和办理关键词只是发现线索，不作为排除其他正文的唯一条件。
2. 按章节和条款边界分窗，设置大小上限和有限重叠。超长条款分段时仍保持原条款 ID 和精确字符区间。
3. 模型对各窗口输出事项候选、锚点条款和理由；纯职责、目的、处罚及禁止要求可标为非办理内容，也可作为事项补充依据。
4. 归并同一制度、同一锚点或明显重复的候选。禁止仅凭模糊名称将不同对象的事项合并；不确定时保留候选并提示复核。
5. 给模型提供当前制度的标题/条款目录，选择事项所需补充条款；加载被选择的正文后再抽取。选择不存在的条款、超出预算或所需材料不足时明确记录，不截断后宣称完整。
6. 自动进行同文关键内容检查：事项相关候选条款中出现材料、期限、审批、例外等内容，而卡片没有相关字段时，生成遗漏疑点。该检查只是提示，不证明完整性。

跨文补充仅在明确引用或人工指定时列入来源。其他语义相似文件可以列为“可能相关”，审核确认前不纳入确定规则。

## 抽取与验证

先提供明确 JSON Schema 和小型示例，强调条件不是动作、执行方不是审批方、禁止随意调换不是禁止一切调换。模型输出不合法时只做有限次数的格式/语义反馈重试，不静默无限回退。

程序检查：字段结构、每个确定字段的来源、引文位置、来源白名单、数字与单位的原文支持、角色及顺序关系的引用有效性。任一字段失败都保存原始候选和具体原因；不能把无效字段直接丢掉后标记完整成功。

语义核查重点：义务动作与触发条件是否混淆，原则与例外是否分开，角色是否被替换，材料和期限是否遗漏。无法由程序证明的内容列为复核疑点，不能输出“已验证正确”。

## 持久化、恢复与更新

独立表：`policy_card_runs`、`policy_card_document_tasks`、`policy_card_candidates`、`policy_card_sources`、`policy_card_reviews`。

运行保存配置快照、模型、提示词/schema 版本和来源快照。文档任务以 pending/running/succeeded/failed 管理，恢复支持接管中断任务；发现、归集、抽取各阶段分别保存检查点，避免整份制度重跑。

候选 JSON 与原始模型响应分开保存，审核历史追加写。审核导入必须匹配卡片 ID、候选版本和来源指纹；来源变化或被他人更新时拒绝覆盖。

增量以制度当前结构版本、文档效力信息和原文指纹为准，纳入模型及 schema/prompt 版本。指纹不变时复用；变化时将受影响卡片标记过期并新建候选版本。原始卡片和审核记录保留，不做破坏性覆盖。

每个卡片字段保留细粒度来源依赖；首版重建粒度为制度，避免修改无关条款时遗漏事项发现结果变化。后续可优化为事项级重建。

## 使用入口与复核产物

独立 CLI 支持按制度/批次运行、恢复、查看状态、检查过期、导出和导入复核。

HTML 报告展示事项、分情形办事卡、疑点、原文及引用位置，不要求用户写标准答案。JSON 复核文件供批量通过、拒绝或修正；首版不另外建设在线审核平台。

卡片检索和详情作为独立服务函数。是否接入正式 MCP 以及是否影响问答排序，另行通过真实问题验证；本次不改变当前正式问答行为。

## 验证与验收

离线测试覆盖：不同情形分离、all/any 条件、字段证据、引文唯一重定位、未知角色、时间与例外、虚构来源拒绝、无效候选保留、检查点恢复、审核并发冲突、来源变更失效、HTML 转义。

真实试验先选宿舍调整，再选择学费减免、学生证补办等完整事项，实际数量根据入库来源完整性确定，不拿无依据题目凑数。检查每项字段及来源，不只看模型调用成功。

住宿调整至少应准确表达：特殊情况触发申请、按规定流程申请、审批通过前提、后勤执行、房源约束、原则办理月份、特殊原因可随时申请；审批部门在原文未明确时不得生成。另需区分退宿、假期留校与调换宿舍，不能因都涉及住宿而混为一个办理事项。

产物必须可查看、可追溯、可恢复，失败有具体原因。真实模型达不到语义验收时如实输出 needs_review/invalid 和分析，不把试验失败包装为生产可用。
