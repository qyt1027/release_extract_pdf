# 复杂 PDF 表格处理实现计划

目标：使完整文字层中的合并单元格表格可以可靠读取、跨页接续，说明不再被识别为独立制度条款。

设计依据：用户已认可按单元格提取、评分明细与分组说明关联、跨页接续及表内编号保护的方案，并要求通用实现。

约束：不按文件名或具体条目编码写特例；不丢弃表外图像中的文字；保留原页码与单元格坐标；无法核对完整性时回退原 OCR；简单表格沿用现有路径。

## 第一步：原生表格提取与跨页接续

- 创建 `parsers/pdf_tables.py`：`extract_structured_page(page, source_id, source_name)` 返回内容块或 None；恢复单元格跨度，逐字符校验文字层覆盖；表外图像返回待识别区域。
- 创建 `core/structured_tables.py`：单元格生成 HTML、评分行及分组说明；`merge_continued_tables(blocks)` 只连接页码相邻、列位置与表头一致、页边界接续且中间没有新标题的表格。
- 修改 `parsers/mineru.py`：复杂表格优先结构化提取；仅表外图像区域请求 OCR；多页批次不吞并结构化表格页。
- 测试先证明旧解析器没有结构字段；再覆盖跨行、跨列、重复表头、说明续句、独立新表和不完整文字层回退。

## 第二步：保护制度条款及检索文本

- 在现有文本内容块上使用 `raw.structured_table` 保存结构，兼容当前 MinerU 文本流程。
- 修改 `policy/pipeline.py` 和 `processing/text.py`，把结构化表格视为不可按内部编号切分的整体。
- 为 `PolicyClause` 增加 `tables`，保存到兼容新增的 JSONB 字段；已有记录默认为空列表。
- 修改 `policy/clause_export.py` 导出 `tables`；原有 `raw_text` 保留可读的评分行、分组说明，检索仍使用纯文本。
- 验证说明 1、2、3 不生成正文条款，跨页范围、HTML 和单元格结构在存储、导出边界不丢失。

## 第三步：原文件和兼容性验证

- 增加本地表格预览命令，生成结构化 JSON 和可查看的 HTML，预览不改源文件和现有数据库。
- 用原奖学金细则第 10–13 页核对分值、说明及跨页句子；生成修改后的预览结果。
- 运行相关回归与完整测试集，检查旧简单网格表、正文页码清理、DOC 本地读取及普通条款保持有效。

本工作区是无 Git 元数据的项目副本，直接修改并验证，不创建分支或提交。由当前会话顺序执行，阶段完成后向用户说明结果。
